CertSmith 0.14.0 is the first release published from a public repository, under the Apache License 2.0.

## Install or upgrade

```sh
bash -c "$(wget -nv -O- https://raw.githubusercontent.com/CautiousCapsLock/certsmith/main/get.sh)"
```

An upgrade keeps your settings and data, and restores the previous version if the new one does not start. The
archives are attested: `gh attestation verify certsmith-0.14.0-linux-amd64.tar.gz --repo CautiousCapsLock/certsmith`.

## New

- **FortiGate: ZTNA server certificates.** Test connection lists the ZTNA servers the device reports (virtual IPs
  and the virtual hosts something uses); tick the ones that should receive the certificate. Only the ticked entry
  is replaced, and the change is rolled back with the rest if a call fails. Certificates are named
  `<prefix>-<name>-<date>-<serial>`, so the device's certificate list says which is which. SSL VPN is no longer
  offered on FortiOS 7.6 and later, where it does not exist.
- **FortiClient EMS** (monitored). EMS has no API for installing a server certificate, so CertSmith watches the
  console (443) and the FortiClient port (8013) and alerts when either serves a different certificate, an
  incomplete chain, or one about to expire. It can run with no certificate chosen, as a plain monitor.
- **Download a certificate and its private key** as a password-protected PKCS#12 file or PEM files, for a device
  CertSmith cannot deploy to. It asks for your own password and is recorded in the audit log.
- **Proxmox VE:** the target dialog explains the node name and how to create the API token and give it the one
  privilege it needs (`Sys.Modify`), with an optional hardening step.
- **Probes:** an address given as an IP is not listed twice when a name you added resolves to exactly that IP.

## Changed

- Changing only the addresses to verify, or a certificate you chose to trust, no longer makes a deployed target
  need a manual deployment again.
- Target rows are laid out in aligned columns, each checked address on its own line with its state at the right,
  and "Action needed" is no longer drawn as an error. Test connection sits beside the token.
- A FortiGate that refuses to import the same certificate under a second name is handled: the copy it already has
  is used.
- `get.sh` uses `wget` when it is present, and `curl` otherwise.

## Security

- Signing out now ends all of that user's sessions, so a copied session cookie stops working at once.
- The session cookie is marked Secure when a trusted reverse proxy says the browser used HTTPS.
- Stricter response headers (Content-Security-Policy `base-uri` and `object-src`, Permissions-Policy and the
  cross-origin policies).
- The database file is flushed to disk before it replaces the old one.
- A webhook target does not follow redirects, refuses to send a private key over plain HTTP, and the local-files
  target does not write through a link planted in a shared directory. Commands it runs no longer receive the master
  key in their environment.
- The systemd unit also hides other processes' `/proc` entries, and the release workflow attests every archive.
- [SECURITY.md](https://github.com/CautiousCapsLock/certsmith/blob/main/SECURITY.md) now lists the design's known limits.

## Notes

- Signing out ends **all** of that user's sessions, in every browser, not only the one used.
- ZTNA server certificates have been exercised on FortiOS 8.0 only. The 7.6 object model comes from Fortinet's
  API specification and automated tests.
